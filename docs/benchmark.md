# V0.1 基准测试

## 目的

基准测试用于回答“检测器是否找到人物”和“识别器是否正确命名角色”两个不同问题。检测不到人物的图片不能被算作角色识别错误，否则会掩盖检测器问题。

## 数据集

使用用户拥有的 100～300 张图片，按姿态和人物数分组：

```text
benchmark/
├─ front/
├─ side/
├─ back/
└─ multi/
```

建议另存一份不进入 Git 的标注表，至少记录图片 ID、真实人物框、人物数、角色 Tag、姿态、遮挡和特殊服装情况。原图不上传、不提交；若需要调试裁剪，保存到本地临时目录并在测试后清理。

## 固定运行条件

每次报告记录：应用 commit、Worker 版本、检测器/识别器模型 ID、上游 revision、模型锁文件 SHA-256、预处理版本、裁剪配置、阈值策略、CPU/GPU、操作系统、Python/运行时版本和运行时间。未下载模型或未提供真实标注时，只能运行协议/健康检查，不能产出准确率结论。

## 必须输出

- 人物检测召回，以及每张图人物数是否正确；
- 检测成功图片的角色 Top-1、Top-5 命中；
- 自动分类准确率（仅统计符合自动分类条件的结果）；
- 待确认率、未识别率、无人物率、处理失败率；
- 正面/侧面/背面/多人物分组结果；
- 每图与每人物耗时、失败原因；
- 混淆较多的角色对或相似角色组；
- 检测失败与识别失败的分开计数。

## 判定纪律

Top-1 分数、Top1/Top2 margin 和多尺度一致性是分类策略信号，不是模型准确率。阈值必须从配置读取，报告明确写出阈值版本。低置信度、姿态困难、强遮挡、裁剪冲突或模型冲突进入待确认；模型没有对应 Tag 时进入未识别。

## 可复核结果

每次运行写出不含原图的结构化报告（JSON/CSV）和可选可视化索引。结果应包含图片相对 ID、检测框、detection_id、裁剪类型、Top-5、最终状态、耗时和错误码。可视化默认引用本地文件路径，不将图像嵌入遥测或网络服务。

## 建议验收门槛

项目目前没有足够的真实测试结果，因此不预设“达到某准确率即可发布”。首次报告完成后，维护者应基于检测召回、Top-5、自动分类准确率、待确认率、速度和资源占用共同决定阈值，记录在新的 ADR 或版本验收记录中。
