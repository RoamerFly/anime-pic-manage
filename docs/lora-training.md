# 角色 LoRA：从识别标注到训练

这条链路把「角色识别 → 人工矫正」的结果变成可用的角色 LoRA，全程在本机完成，训练器不是本应用的一部分。

```text
角色识别（人工矫正）
→ 导出 kohya 训练集（裁剪 / 去重 / WD14 打标）
→ 一键调用本机 kohya_ss / sd-scripts 训练
→ LoRA 复制进 ComfyUI 的 models/loras
→ 在「AI 生图」页选用
```

## 1. 导出训练集

在「AI 生图 → 训练集导出（角色 LoRA）」里选择角色并导出。规则与社区（kohya sd-scripts）一致：

- 每张图按人工标注的人物框裁剪（`person` / `head` / `bust` / `large` / 整图），短边缩放到目标分辨率。
- 感知哈希去重，阈值可调；重复图会被跳过并计入结果。
- WD14 自动打标生成 caption，格式为「质量前缀 + 触发词 + Danbooru 标签」，逗号后不留空格。
- 产物：`<输出目录>/<角色>/NNN.png` + `NNN.txt`、`dataset.toml`、`dataset-manifest.json`。

推荐规模是每个角色去重后 20～40 张：太少学不到角色特征，太多会把画风细节一起学进去。

导出**只清理本工具自己写出的训练集**：目标角色目录里存在非本工具写入的文件时，导出会报错停止，不会覆盖手工整理的素材。

## 2. 准备训练器

本应用不打包、不下载训练器，需要你自己准备：

- kohya_ss（内含 `sd-scripts/` 与 `venv/`），或直接克隆 sd-scripts 并按其说明建好环境。
- 目录里需要有 `train_network.py`（SD1.5 / SD2.x）或 `sdxl_train_network.py`（SDXL）。
- 训练底模是 `.safetensors`，且**必须与 LoRA 家族匹配**：SD1.5 的 LoRA 不能配 SDXL 底模，反之亦然。

在「设置 → 生图配置 → LoRA 训练」里填写训练器目录、可选的 python.exe、底模和输出目录，然后用「检测训练器」和「检查 torch / CUDA」确认状态。Python 留空时会依次尝试训练器目录下的 `venv` / `.venv`、便携版 Python，最后才回退到系统 PATH。

## 3. 训练

在「AI 生图 → LoRA 训练（本机 kohya）」里：

1. 确认「训练集配置」指向刚导出的 `dataset.toml`（导出成功后会自动填入）。
2. 填写 LoRA 名称，建议直接用触发词。
3. 选择预设（SD1.5 / SDXL · 6GB 显存）或自定义参数。
4. 开始训练；日志会实时显示，可以随时停止，也可以离开页面再回来接着看。

生成的参数就是 sd-scripts 的命令行参数，可以在页面上展开「查看将要执行的命令」核对：

- `--dataset_config` 指向导出的 `dataset.toml`，分辨率、bucket 与 repeats 由训练集配置决定；命令行不再重复传 `--resolution` / `--train_data_dir`（sd-scripts 会拒绝同时出现）。
- 6GB 显存的保守起点：`network_dim 32 / alpha 16`、`AdamW8bit`、`--gradient_checkpointing`、`--cache_latents`、`--network_train_unet_only`、batch 1。
- 中途按 `--save_every_n_epochs` 产出的 `.safetensors` 会实时出现在「训练产物」里，可以直接「安装到 ComfyUI」；本应用只复制，不删除原文件。
- 训练会占满显卡与较多内存，期间不建议同时做识别/相似度扫描或出图。

### 实测：6 GB 显存下的取舍

在 RTX 3060 Laptop（6 GB）上实测过两种配置：

| 配置 | 显存占用 | 2000 步耗时 | 结论 |
| --- | --- | --- | --- |
| SD1.5 · 512px · 48 张 · batch 1 | **约 2.8 GB** | 约 16 分钟 | 6 GB 卡很轻松，推荐先用它跑通 |
| SDXL · 768px · batch 1 | 约 5.9 GB（贴近上限） | 约 42 秒/步 | 会触发 WDDM 显存换页，慢到不可用 |

教训有两条：

- `--network_train_unet_only` **不会**把两个 CLIP 文本编码器从显存里挪走（SDXL 约 1.4 GB）。真要在小显存上跑 SDXL，还要勾选「缓存文本编码器输出（小显存）」（即 `--cache_text_encoder_outputs`，SDXL 预设默认已勾选）。该选项要求关闭 caption 洗牌，应用会自动在同目录生成 `dataset.cache-te.toml` 供这次训练使用，原配置不动。
- 训练日志是实时读取子进程输出的，应用会以 `PYTHONUNBUFFERED=1` 启动训练进程，否则日志会攒够一块才刷新。
- 显存顶到 90% 以上时，Windows 会用内存兜底（WDDM），此时 GPU 利用率显示 100%，但速度会掉一到两个数量级。看到「每步几十秒」就该降分辨率或换 SD1.5。

如果显存余量允许，SDXL 版本对画风还原更好；只是想验证「触发词能出角色」的话，SD1.5 足够。

## 4. 判定训练是否有效

训练结束后用固定 seed 出图对比：只改触发词、不改其他提示词，看角色是否稳定出现；再改姿势/服装描述，确认学到的是角色而不是某张训练图的构图。本应用自己的角色识别也可以当验证手段：对生成的图跑一次识别，看 Top-1 是否落到该角色。

注意：**内建识别模型不一定有这个角色的标签**。当前使用的 `animetimm/resnet101.dbv4-full`（约 1.2 万个标签）里就没有你要的角色，只有一部分热门角色，所以把她的图拿去识别只会得到「未识别」或错误的近邻标签。遇到这种情况有两条路：

1. 在「角色识别」里人工矫正一批（该角色 + 至少另一个角色，各 3 张以上），训练应用内的**个人模型**，她才会变成可识别类别；
2. 或者直接把这些矫正结果导出成训练集，喂给 LoRA 继续迭代。

## 许可证与边界

- kohya_ss、sd-scripts 是独立项目，各有自己的许可证；本应用只调用本机已安装的实例，不打包、不分发、不修改它们的代码。
- WD14 打标权重来自 Hugging Face（`SmilingWolf/wd-swinv2-tagger-v3` 等），首次导出按需下载到本机缓存，不随安装包分发。
- 训练底模与训练产出的 LoRA 许可证由各自上游决定，是否允许商用与再分发需自行核对。
